# 要件定義書 — 不思議のダンジョン Web クローン

## 1. 目的

「ドラゴンクエスト 少年ヤンガスと不思議のダンジョン」風のローグライクをブラウザで動作するクローンとして実装し、
AI（Claude Fable 5.1）の設計・実装能力を評価する題材とする。

- 権利物のアセット（画像・音・固有名詞のデータ）は一切使用しない。名称は DQ 風のオリジナルとする。
- ブラウザ完結（サーバ不要）。`vite build` の静的ファイルのみで動作する。

## 3. 機能要件

### 3.1 ダンジョン
- 48×24 タイル。3×2 のセクターに分割し、各セクターに部屋を 1 つ配置する。
- 隣接セクター間をランダム全域木で接続し、さらに 1 本の追加接続でループを作る。
- 全床タイルは互いに到達可能であること（テストで 100 シード検証）。
- 階段はいずれかの部屋にランダム配置。

### 3.2 ターン制
- プレイヤーの 1 行動 → 仲間の行動 → 敵の行動 → ターン終了処理。
- 敵・仲間は `speed` 回行動する（ドラキー等は 2 回）。
- ターン終了処理: 満腹度減少、自然回復、状態異常の経過、壺の調合進行、敵の追加湧き。

### 3.3 戦闘
- ダメージ = `max(1, floor((攻撃力 − 防御力/2) × 乱数[0.875, 1.125)))`
- 命中率 90%。
- 撃破時に経験値。プレイヤーがトドメを刺した場合、モンスターごとの確率で仲間になる（最大 2 体）。

### 3.4 アイテム・壺・錬金
- 所持上限 20。壺の中身は所持数にカウントしない。
- 壺には壺を入れられない。調合中の壺には出し入れできない。
- 錬金の壺: 入れた素材の集合がレシピに一致した瞬間に調合が始まり、`turns` ターン後に完成品が壺内に生成される。
  どのレシピの部分集合にもならない素材は入れられない。
- 合成の壺: 同じ種類（武器同士／盾同士）を入れると先に入っている装備に修正値が吸収される（+1 ボーナス）。
- 変化の壺: 入れたアイテムが壺・ゴールド以外のランダムなアイテムに変わる。

### 3.5 仲間
- 敵と同じ AI 基盤で、敵→隣接攻撃／プレイヤー近傍の敵へ接近／プレイヤーへ追従の優先順で行動。
- プレイヤーが仲間のいるマスへ移動すると位置を入れ替える。
- フロア移動時はプレイヤーの近くに再配置される。

### 3.6 拠点・店・図鑑・リレミト
- 詳細は [06 拠点・ショップ・図鑑](06_拠点・ショップ・図鑑.md)、[07 仲間システム](07_仲間システム.md)、[08 ダンジョンテーマとモンスターハウス](08_ダンジョンテーマとモンスターハウス.md) を参照。

### 3.7 記録・リプレイ
- プレイヤー入力はすべて `Command` データとして `GameSession.execute()` に渡される。
- `seed` + `Command[]` から `GameSession.replay()` で同一状態を再構築できる。
- ブラウザでは `P` キーでリプレイ JSON をクリップボードへ、`O` キーで読み込み。

## 4. 非機能要件

| 項目 | 要件 |
| --- | --- |
| 決定論 | すべての乱数はシード付き `SeededRng` を通す。`Math.random` はゲームロジックで使用禁止 |
| 分離 | ゲームロジック（`src/domain`）は DOM・Canvas に依存しない。Node 上でテスト可能 |
| 設計原則 | SOLID。データ（マスター）とルール（サービス）と状態（State）を分離 |
| 性能 | 地形はフロアごとに 1 回だけオフスクリーン描画しキャッシュ。毎フレームはスプライトとライティングのみ |
| 対応環境 | 最新の Chromium / Firefox / Safari。キーボード操作のみ |
